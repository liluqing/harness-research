# Phase 1：产品与原型

> **定位：** 将用户原始需求转化为 PRD + 轻量原型。是整个 Harness 流程的起点。
> **Agent 帽子：** 产品经理 + 交互设计师
> **输入：** 用户原始需求（聊天记录、想法、竞品链接、文档）
> **产出：** `prd/<功能名>-prd.md` + 可选原型 HTML

---

## 流程总览

```
用户原始需求
    ↓
STEP 1: 收集与整理
    ↓
STEP 2: 需求澄清（产品层决策树）
    ↓
STEP 3: PRD 概要 → 用户确认
    ↓
STEP 4: 生成轻量原型（可选，基于概要）
    ↓
STEP 5: 用户反馈 → 调整 PRD + 原型
    ↓
产出: PRD + 原型 HTML
```

---

## STEP 1：收集与整理

Agent 读取用户提供的所有信息，产出「需求快照」：

```
【需求快照】<功能名>

一、已知信息
- 用户明确提到的需求点
- 用户提到的场景/角色
- 用户给的参考/竞品

二、信息缺口
- 需要澄清的业务规则
- 需要确认的范围边界
- 需要明确的优先级
```

不发给用户——这是 Agent 内部整理，用于准备 STEP 2 的问题。

---

## STEP 2：需求澄清（产品层决策树）

### 2.1 决策树逻辑

与 Spec 决策树同构，但判断标准是产品层面而非技术层面。

**分支 A（Agent 自己定）—— 满足任一：**

| 条件 | 示例 |
|------|------|
| 行业通用产品模式 | 用户管理 = 列表 + 增删改查 + 搜索 |
| 竞品有标准做法 | 后台管理的导航结构、表单布局 |
| 对功能方向影响小 | 按钮文案、默认排序规则 |
| 项目已有同类产品可参考 | 已有的管理后台模块模式 |

Agent 自己定的决策，在 PRD 概要中一句话告知：
> **Agent 已定：** 用户列表默认按创建时间倒序；每页 20 条；支持姓名/手机号搜索。

**分支 B（必须问用户）—— 满足任一：**

| 条件 | 示例 |
|------|------|
| 影响业务逻辑 | 审批流程、权限模型、计费规则 |
| 影响交付范围 | 这期做不做移动端、做不做数据导出 |
| 影响产品定位 | 面向内部管理员还是外部客户 |
| 涉及合规/法务 | 数据留存期限、隐私合规要求 |
| 多部门利益冲突 | A 部门要这样，B 部门要那样 |

走分支 B 时，给出 2~3 个选项 + **产品视角的建议**：
> **需要你定（产品决策）：**
> 1. 用户注册方式 → A. 手机号+验证码 B. 邮箱 C. 手机号+邮箱。建议 A，B 端产品手机号更直接。

**产品层约束：**
- 每次 ≤ 5 个决策点（产品层问题天然比 Spec 层多）
- 超过 5 个 → 优先问范围/定位问题，细节问题走分支 A

### 2.2 产品层 vs Spec 层判断对比

| 维度 | 产品层（Phase 1） | Spec 层（Phase 3） |
|------|------------------|---------------------|
| Agent 定的范围 | 行业产品模式、竞品做法 | 技术约定、命名规范 |
| 必须问的范围 | 业务逻辑、范围、定位 | 数据策略、架构选择 |
| 问题上限 | 5 个 | 3 个 |

## STEP 3：PRD 概要 → 用户确认

格式：

```markdown
【PRD 概要】<产品/功能名>

**一句话定位：** 这是什么产品/功能，解决什么问题

**目标用户：** 谁在用

**核心场景：** 2~3 个核心使用场景

**功能范围（本期）：**
- 功能 A
- 功能 B
- 功能 C

**后续考虑（不在本期）：**
- 功能 D
- 功能 E

**关键业务规则：**
- 规则 1
- 规则 2

**Agent 已定：** 
- 产品模式决定 1
- 产品模式决定 2

**需要你定（N 个）：**
1. 决策描述 → A/B/C 选项 + 建议
2. ...
```

发给用户 → 等确认 → 展开完整 PRD。

---

## STEP 4：生成轻量原型（可选）

### 4.1 触发条件

满足以下任一即建议出原型：
- 功能涉及 ≥ 3 个页面间的数据流转
- 业务规则需要在界面上体现（如状态变更、权限控制）
- 用户明确表示「先看看效果」
- 涉及多角色交互（管理员 vs 普通用户视角）

### 4.2 原型原则

```
轻交互：能点能跳转即可，不做交互动效
重数据：用真实感数据，不写「测试数据」「XXX」
重功能：展示功能逻辑，不做视觉设计
```

### 4.3 原型产出

一个自包含 HTML 文件，包含：
- 关键页面（列表/详情/表单/弹窗）
- 页面间跳转逻辑
- 真实感示例数据
- 状态切换（空态/正常态/错误态）

模板：`shared/prototype-brief.md`（设计稿）

---

## STEP 5：用户反馈 → 调整

用户对 PRD 和原型的反馈 → Agent 调整 → 再次确认。

循环直到用户说「可以，进入开发」。

---

## 完整 PRD 输出

确认后，展开为完整 PRD 文档。模板：`templates/prd.md`。

写入：`prd/<功能名>-prd.md`。
